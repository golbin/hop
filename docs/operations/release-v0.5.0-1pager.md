# HOP 0.5.0 준비

## 배경과 문제

이번 세션의 rhwp 0.9.0 통합과 데스크톱 편집 개선 전체를 다시 검토한다.
앞선 0.4.6 후보 빌드는 중단하며, 배포 버전은 0.5.0으로 정정한다.
작업 기록이 누적되어 현재 구현과 다른 문서 및 중복 설명도 정리해야 한다.

## 목표와 범위

1. origin/main 이후 전체 구현의 정확성, 부작용, 중복과 불필요한 상태를 검토하고 개선한다.
2. 저장소 문서를 모두 읽고, 유지할 지식은 현재 운영·설계 문서로 통합한다.
   완료한 계획·트리아지·QA 기록은 git history에 남기고 삭제한다.
3. 버전 소스와 릴리스 노트를 0.5.0으로 맞춘 뒤 작업 브랜치를 main에 머지한다.
4. 머지 결과에서 필수 테스트를 통과한 다음 태그·릴리스를 만들고 빌드·배포한다.

upstream 파일 직접 수정, 관련 없는 기능 추가, 기존 태그 이동과 이력 재작성은 하지 않는다.
PR에서 가져온 개선은 기존 cherry-pick 출처를 유지한다.

## 구현 방침

문제의 원인을 소유하는 경계에서 고친다. upstream이 제공하는 동작은 재사용하고,
현재 요구에 필요 없는 추상화·호환 경로·상태·문서를 제거한다. 생성 WASM은 provenance와
고정 소스로 검증한다. 문서와 구현이 다른 부분은 고치거나 남은 제한으로 명시한다.
기존 긴 bootstrap/toolbar는 전체를 복제·재설계하지 않고 이번 동작의 소유권을 확인한다.

## 검증과 복구

수정 중에는 필요한 회귀 테스트만 실행한다. 전체 테스트, upstream 계약, Rust fmt/clippy,
Studio 타입 검사·빌드는 main 머지 후 최종 실행한다. 이후 v0.5.0 태그의 전체 플랫폼
배포 workflow에서 macOS 서명·공증, Linux ABI, updater 서명·manifest와 고정 asset 이름을
확인하고 공개한다. 실제 GUI 검증 범위와 자동화로 확인하지 못한 항목을 구분한다.

실패하면 해당 수정만 일반 커밋으로 되돌리거나 보완한다. 잘못된 산출물은 공개하지 않고,
기존 안정 릴리스와 태그를 유지한다. 완료 후 이 작업 계획도 삭제하고 운영 지식만 남긴다.
